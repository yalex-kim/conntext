# 메모 조회

사용자가 찾는 내용: $ARGUMENTS

conntext MCP 서버의 `recall` 도구에 질문을 그대로 넣어 호출한다. 결과가 부족하면 핵심 단어만 뽑아 한 번 더 찾는다.

메모에서 찾지 못했거나, 질문이 정리된 지식이 아니라 지난 대화 자체를 묻는 것이면("그때 무슨 얘기를 했지", "어떤 명령으로 고쳤지", "그때 어떤 오류였지") `search_sessions`로 지난 세션 대화록을 한 번 찾는다. 고유한 단어(파일 이름, 명령, 오류 문구)로 찾고, 사용자가 기간을 말했으면 `after`·`before`를 넣는다. 걸린 세션을 더 읽어야 하면 `session_id`와 줄 범위로 다시 부른다. 세션 대화록에서 찾은 내용은 "지난 세션(날짜, 플랫폼)에서"라고 출처를 밝혀 답한다. 대화록은 정리된 메모가 아니라 그때의 대화라 바뀌었을 수 있다.

결과의 각 메모에는 출처 등급이 붙어 있다. 등급에 따라 믿을 수 있는 정도가 다르므로 답할 때 구분해서 다룬다.

- **[내 메모]**: 사용자가 직접 적은 내용이다. 사실로 다룬다.
- **[팀 지식 · 작성자]**: 팀 동료가 공유한 내용이다. 누가 적었는지 함께 말한다. 사용자가 더 묻고 싶을 때 찾아갈 사람이 된다.
- **[세션 자동 추출·미확인]**: 지난 세션에서 자동으로 뽑혔고 아무도 확인하지 않은 내용이다. 근거로 쓸 때는 미확인이라고 밝힌다.

답은 질문에 대한 결론부터 쓰고, 근거로 쓴 메모를 `m:번호`로 붙인다. 메모끼리 내용이 어긋나면 날짜가 최근인 쪽을 따르되 어긋난다는 사실을 알린다. 찾지 못했으면 찾지 못했다고 말하고 추측으로 채우지 않는다.

답을 마친 뒤, 실제로 근거로 쓴 메모의 id를 `mark_used` 도구로 알린다. 이 기록으로 자주 쓰이는 메모가 다음 검색에서 우선되고, 미확인 메모는 충분히 쓰이면 정식 메모가 된다. 결과에 나왔지만 쓰지 않은 메모는 넣지 않는다.

사용자가 메모 내용이 틀렸다고 하면 고친 내용을 받아 `remember` 도구에 `replaces`로 그 메모 id를 넣어 저장한다. 웹에 가서 고치라고 안내하지 않는다.
