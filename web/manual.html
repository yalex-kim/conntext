Conntext 사용자 매뉴얼플러그인 0.1.0

Conntext 사용자 매뉴얼

Claude Code와 OpenCode에 적어 둔 메모와 진행 상태가 다음 세션과 다른 에이전트로 이어지게 하는 서비스입니다. 이 문서는 설치부터 명령어, 메모가 어디로 가는지, 기록을 끄고 지우는 방법까지 다룹니다. 절 번호로 가리킬 수 있습니다(예: "매뉴얼 4.2").

15분 설치

Claude Code 플러그인과 OpenCode 플러그인은 같은 클라이언트(conntext.py)와 같은 설정 파일(~/.conntext/config.json)을 씁니다. 한 번 연결해 두면 두 에이전트가 같은 메모를 봅니다. 장비에 python3과 git이 있어야 합니다.

1.1Claude Code

① 플러그인 설치. Conntext 저장소가 플러그인 마켓플레이스입니다. 터미널에서 다음을 실행합니다. Claude Code 안에서는 /plugin marketplace add …, /plugin install conntext@conntext로 같은 일을 합니다.

터미널
$ claude plugin marketplace add <conntext 저장소 주소 또는 경로>$ claude plugin install conntext@conntext

② 토큰 발급. 웹의 설정 > 연결에서 토큰을 발급합니다. ctx_로 시작하는 값이고, 발급할 때 한 번만 보입니다.

③ 연결. 서버에서 클라이언트를 받아 서버 주소와 토큰을 저장합니다. setup은 저장한 뒤 바로 연결 상태를 확인해 보여 줍니다(1.3).

터미널
$ mkdir -p ~/.conntext/bin && curl -fsSL http://서버:7373/client/conntext.py -o ~/.conntext/bin/conntext.py$ python3 ~/.conntext/bin/conntext.py setup --url http://서버:7373 --token ctx_…

Claude Code의 훅과 명령어는 ①의 마켓플레이스 설치로 등록됩니다. 받은 파일만으로는 훅이 등록되지 않습니다. 설치 뒤 새로 시작한 세션부터 맥락이 들어갑니다.

1.2OpenCode

1.1의 ③(클라이언트 받기와 setup)을 먼저 한 뒤 한 줄을 더 실행합니다.

터미널
$ python3 ~/.conntext/bin/conntext.py install opencodeOpenCode에 설치했습니다: /home/me/.config/opencode명령어: /remember /recall /resume /handoff /forgetOpenCode를 다시 시작하세요.

OpenCode 설정 폴더(OPENCODE_CONFIG_DIR, 없으면 ~/.config/opencode)에 플러그인(plugins/conntext.js), 명령어 다섯 개(commands/*.md), opencode.json의 mcp.conntext 항목을 넣습니다. 기존 opencode.json은 opencode.json.conntext-backup으로 남깁니다.

1.3연결 확인

저장소 폴더에서 status를 실행합니다. 마지막 줄의 저장소가 메모의 범위가 됩니다(4.3).

터미널 · 예시
$ python3 ~/.conntext/bin/conntext.py status연결됨: http://서버:7373사용자: 정도현 <dohyun@conn.example>팀: Connectivity 팀이 폴더의 저장소: git@github.com:connectivity/ble-gateway.git세션 기록: 켜짐

연결되지 않으면 연결 실패: HTTP 401 (토큰이 유효하지 않습니다)나 연결 실패: 주소 (원인)이 나옵니다. 9장을 보세요.

2다섯 명령어

Claude Code에서는 플러그인 이름이 앞에 붙어 /conntext:remember처럼 쓰고, OpenCode에서는 /remember로 씁니다. 명령어 없이 "이거 기억해 둬", "어제 하던 거 이어서"처럼 말해도 에이전트가 같은 도구를 부릅니다.

명령어언제 쓰나돌아오는 것
/remember다음 세션이 알아야 할 결정, 원인, 규칙, 선호를 남길 때저장 결과 한 줄(주제, 종류, 범위, 대체한 메모)
/recall전에 적어 둔 것이나 팀 규칙을 찾을 때등급이 붙은 메모와 그것을 근거로 한 답
/resume지난 세션에서 하던 일을 이어서 시작할 때진행 상태 브리핑과 다음에 할 일 제안
/handoff여기까지 하고 넘길 때저장한 진행 상태
/forget메모를 지우거나 방금 한 저장을 취소할 때삭제·되돌리기 결과

2.1/remember [내용] [--global]

적은 문장을 다듬지 않고 그대로 저장합니다. 범위는 지금 저장소이고, --global을 붙이면 모든 저장소에 적용됩니다(4.3). 결과 한 줄로 저장이 의도대로 됐는지 확인합니다.

Claude Code · 예시
> /conntext:remember 스테이징 배포는 목요일 오전만 가능하도록 변경됨. 화요일은 QA 회귀 테스트와 겹친다저장됨 m:12 → [스테이징 배포] · 지식 · 범위: 저장소 ble-gateway이전 메모 1건 대체: "스테이징 배포는 화요일 오전만 가능" (10/25)
> /conntext:remember PR 설명에는 테스트한 기기 모델과 펌웨어 버전을 꼭 적어 줘 --global저장됨 m:15 → 항상 적용 목록 · 지시·선호 · 범위: 전체

둘째 줄에는 상황에 따라 다음 문구가 붙습니다.

  • 이전 메모 1건 대체: … 기존 메모를 바꾸는 내용이라 이전 메모를 대체됨으로 돌렸습니다.
  • 관련 메모에 이어 붙임: … 기존 메모를 보충하는 내용이라 같은 주제 문서에 넣었습니다.
  • 이미 있는 메모와 같은 내용이라 새로 만들지 않고 m:N에 합쳤습니다
  • 새 주제 문서를 만들었습니다., 민감 정보 N건을 마스킹했습니다.

작업 방법은 절차로 저장됩니다. 순서와 명령이 있는 메모(“배포하려면 먼저 … 그다음 …”, 번호 매긴 단계)는 절차로 분류되고, 언제 쓰는 절차인지 한 줄(언제)이 함께 붙습니다. 절차는 지식과 다른 절차 문서에 모이고, 세션을 시작할 때 “언제 → 절차 제목”만 들어갑니다. 에이전트는 그 작업을 하게 되면 시작하기 전에 절차 문서를 꺼내 따릅니다.

Claude Code · 절차 저장
> /conntext:remember 게이트웨이 재시작 순서: mqtt-broker 먼저, 그 다음 ble-bridge. 반대로 하면 bridge가 재연결 폭주를 일으킨다저장됨 m:7 → [게이트웨이 재시작 순서] · 절차(언제: 게이트웨이 재시작할 때) · 범위: 저장소 ble-gateway

언제는 에이전트가 절차를 꺼낼지 정하는 유일한 단서라, 흐릿하면 웹의 메모 화면에서 “언제 쓰는지 → 고치기”로 작업이나 증상을 구체적으로 고칩니다(예: “스테이징에 배포할 때”, “로그인 테스트가 타임아웃으로 실패할 때”). 세션 기록에서도 시행착오 끝에 성공한 작업 방법이나 사용자가 바로잡은 방법이 절차 후보로 뽑힙니다.

내용 없이 부르면 에이전트가 이번 세션에서 남길 만한 것(결정과 이유, 찾아낸 원인, 저장소의 규칙이나 함정, 검증된 작업 방법, 밝힌 선호)을 많아야 다섯 개 골라 번호를 붙여 제안합니다. 고른 것만 저장하고, 고르기 전에는 아무것도 저장하지 않습니다.

분류가 틀렸으면 /forget last로 되돌립니다. 기존 메모의 내용이 틀렸다고 말하면 에이전트가 고친 내용을 새 메모로 저장하고 이전 메모를 대체됨으로 남깁니다.

2.2/recall [찾을 내용]

내 공간과 소속 팀 공간을 함께 찾습니다. 에이전트는 아래 내용을 받아 결론부터 답하고, 근거로 쓴 메모를 m:번호로 붙입니다. 미확인 메모를 근거로 쓰면 미확인이라고 밝히고, 메모끼리 어긋나면 최근 쪽을 따르되 어긋난다는 사실을 알립니다.

recall 도구가 돌려주는 내용 · 예시
"ble-bridge 연결이 끊겼다 붙었다 해" 검색 결과 3건
[내 메모] m:18 (11/11, 주제: RSSI 임계값 -85dBm)RSSI 임계값 -85dBm 아래로 3초 유지되면 연결을 끊고 재스캔한다
[세션 자동 추출·미확인] m:49 (11/12)원인은 경계값 근처에서 연결과 해제가 반복됐기 때문입니다.
[팀 지식 · 오지민] m:43 (11/8, 주제: 게이트웨이 헬스체크 엔드포인트)게이트웨이 헬스체크 엔드포인트는 /healthz, ble-bridge는 포트 9102

답을 마친 뒤 에이전트는 실제로 근거로 쓴 메모만 사용 기록으로 알립니다. 자주 쓰인 메모는 다음 검색에서 앞에 오고, 미확인 후보는 두 번 쓰이면 정식 메모가 됩니다(5.2).

2.3/resume [이어갈 업무]

이 저장소의 가장 최근 진행 상태와 관련 메모를 가져옵니다. 에이전트는 언제 어느 플랫폼에서 남긴 상태인지, 끝낸 일, 남은 일, 주의점을 짧게 브리핑하고, git status와 최근 커밋으로 지금 저장소와 맞는지 확인한 뒤 무엇부터 할지 제안합니다. 시작은 확인을 받고 합니다.

resume 도구가 돌려주는 내용 · 예시
지난 진행 상태 m:34 (claude-code, 11/11 19:36)요청: 토큰 갱신 테스트 2건이 실패하는데 원인 좀 찾아줘완료: 인증 미들웨어 리팩터링을 완료했습니다. 토큰 검증을 TokenVerifier 클래스로 분리했고 auth 테스트 41건이 모두 통과합니다.남은 일: mqtt-broker 쪽 ACL 캐시가 옛 토큰을 5분간 들고 있어서, 갱신 직후 publish가 거부되는 문제를 아직 확인하지 못했습니다. 다음에 broker/acl_cache.py의 TTL을 확인해야 합니다.

진행 상태가 없으면 이어받을 진행 상태가 없습니다.라고 알리고, 다른 저장소의 최근 상태가 있으면 함께 보여 줍니다. 업무를 지정했는데 진행 상태와 다르면 그 업무를 한 번 더 찾아봅니다.

2.4/handoff [덧붙일 말]

에이전트가 이 세션을 돌아보고, 대화를 보지 않은 사람도 바로 시작할 수 있게 진행 상태를 씁니다. 순서는 요청, 완료(바꾼 파일과 확인 방법), 남은 일(파일과 식별자를 넣어서), 주의(안 된 방법, 확인하지 못한 가정)입니다. 실제로 한 일만 완료에 씁니다.

handoff 결과 · 예시
진행 상태 저장됨 m:34 · 범위: 저장소 ble-gateway이전 진행 상태 1건을 대체했습니다.

진행 상태는 저장소마다 최신 하나만 유효하고 14일 뒤 만료됩니다. 세션이 끝날 때 자동으로도 남으므로(5.2), /handoff는 직접 정리해서 넘기고 싶을 때 씁니다. 작업이 끝난 뒤에도 쓸모 있는 결정은 /remember로 따로 남기세요.

2.5/forget [지울 내용 | last]

삭제는 모든 세션과 에이전트에 영향을 주므로, 에이전트는 어느 메모인지 확인을 받은 뒤에 지웁니다.

  • last: 가장 최근의 저장이나 삭제를 되돌립니다. 결과는 되돌렸습니다.
  • m:42처럼 id를 주면 내용을 보여 주고 확인받은 뒤 지웁니다.
  • 내용으로 지정하면 후보 목록을 먼저 보여 주고, 고른 것을 지웁니다.
forget 결과 · 예시
삭제함 m:12 "스테이징 배포는 목요일 오전만 가능하도록 변경됨. 화요일…"이 메모가 대체했던 이전 메모 m:4를 다시 유효로 돌렸습니다.

지운 메모가 이전 메모를 대체하던 것이었다면 이전 메모가 다시 유효해집니다. 지운 메모는 7일 안에는 되돌릴 수 있고, 7일이 지나면 본문이 실제로 지워집니다. 내용이 틀린 것뿐이라면 지우기보다 고치는 편이 이력이 남아 낫습니다. 팀 공간의 메모는 본인이 올린 것만 지울 수 있습니다(7.3).

3메모가 처리되는 과정

3.1다섯 단계

메모는 서버에 닿으면 아래 순서를 거칩니다. 2단계가 끝나면 바로 검색되고, 나머지 판단은 그 위에 얹는 정보입니다. 판단은 서버 설정에 따라 언어 모델이나 규칙으로 합니다.

3.2관계 판정

같은 공간의 비슷한 메모와 비교해 넷 가운데 하나로 판정하거나, 관계가 없다고 봅니다.

판정뜻결과
중복이미 있는 내용새 메모를 만들지 않고 기존 메모에 합칩니다.
갱신기존 내용을 바꿈기존 메모는 대체됨으로 이력에 남고, 새 메모가 같은 주제 문서에서 적용됩니다.
보충기존 내용에 덧붙임둘 다 유효하고 같은 주제 문서에 들어갑니다.
연관관련 있는 다른 내용서로 연결만 하고, 주제 문서는 따로 정합니다.

세션에서 자동으로 뽑힌 후보는 사람이 적은 메모를 대체하지 못합니다. 갱신으로 판정돼도 보충으로 낮춰 저장합니다.

3.3원문 보존과 되돌리기

웹에서 메모를 고쳐도 원문은 바뀌지 않습니다. 고친 내용이 새 메모로 저장되고 이전 판은 대체됨으로 남아 변경 이력이 보입니다.

저장, 삭제, 후보 확인과 버리기는 저장 내역에 하나씩 남습니다. 저장을 되돌리면 새 메모가 지워지고, 그 메모가 대체했던 메모가 원래대로 돌아오며, 그 저장으로 새로 생긴 주제 문서가 비면 함께 사라집니다. 삭제를 되돌리면 메모가 원래 상태로 돌아옵니다.

4등급과 주입

4.1등급별 적용 방식

메모에는 누가 어떻게 남겼는지에 따라 등급이 붙고, 에이전트에 들어가는 방식이 다릅니다. 에이전트의 기본 동작을 바꾸는 지시는 직접 적었거나 확인한 것만 들어갑니다.

등급생기는 경로세션 시작 때/recall에서유지
m:12내 메모/remember, 웹 입력, 확인한 후보지시·선호는 항상 넣고(최대 12건, 합쳐 1,200자. 넘으면 알리고, 들어가지 않는 지시는 빠짐), 절차는 절차 색인에 “언제 → 제목”만(최대 20개), 지식은 주제 색인에 제목만(예산 안에서 최대 40개 주제, 자주 쓰인 주제 먼저)[내 메모]지울 때까지

건수 한도는 기본 정책 값이며 운영 정책으로 바뀔 수 있습니다.

4.2세션 시작 블록

세션이 시작되면 Conntext가 블록 하나를 에이전트에 넣습니다. 구역 순서는 안내 문구, 지시·선호, 팀 규칙, 진행 상태, 내 절차 색인, 팀 절차 색인, 내 지식 색인, 팀 지식 색인이고, 기본 예산 1,500 토큰 안에서 위에서부터 채웁니다. 예산을 넘는 항목은 그 구역의 뒤쪽부터 빠집니다. 색인에는 본문이 들어가지 않고, 에이전트가 필요할 때 [t:31] 같은 표시로 본문을 꺼냅니다.

  • 절차 색인은 - 게이트웨이 재시작할 때 → 게이트웨이 재시작 순서 [t:3]처럼 언제 쓰는지와 제목을 넣습니다. 에이전트는 그 작업을 시작하기 전에 절차를 꺼냅니다. 지식 색인보다 앞에 있어, 예산이 모자라면 지식 색인이 먼저 줄어듭니다.
  • 지식 색인은 주제 제목만 넣습니다. 지금 작업과 관련 있어 보일 때 에이전트가 검색하거나 꺼냅니다.

블록 끝에는 이 세션의 저장소 식별자(이 세션의 Conntext project: github.com/connectivity/ble-gateway)가 붙습니다. 같은 블록을 웹의 에이전트 화면에서 저장소별로 미리 볼 수 있습니다(6장).

4.3범위: 저장소와 전체

저장소는 git 원격 주소로 식별합니다. git@github.com:connectivity/ble-gateway.git과 https://github.com/connectivity/ble-gateway는 모두 github.com/connectivity/ble-gateway가 되므로, 장비나 접속 방식이 달라도 같은 저장소로 봅니다. 원격이 없으면 local:폴더이름을 씁니다.

  • 저장소 범위(기본): 그 저장소의 세션에만 들어갑니다. 다른 저장소에서 /recall하면 찾히긴 하지만 순위가 낮아집니다.
  • 전체 범위(--global): 모든 저장소의 세션에 들어갑니다. 저장소와 무관한 개인 선호(말투, 커밋 형식)에 씁니다.

5세션 자동 수집

5.1무엇이 서버로 가나

Claude Code는 세션이 끝날 때와 대화를 압축하기 직전에 훅이 대화록 파일(끝에서부터 최대 3MB)을 백그라운드로 보냅니다. 보내기 전에 장비에서 <private> 구간을 지웁니다. OpenCode는 응답이 끝날 때마다 발화와 도구 이름만 담은 스냅샷을 만들고, OpenCode가 끝나거나 300초 동안 대화가 없으면 보냅니다.

긴 세션은 끝나기 전에도 응답 10번마다(운영 정책으로 바꾸거나 끌 수 있음) 체크포인트로 올라갑니다. 서버는 그때마다 진행 상태를 갱신해, 같은 저장소의 다른 에이전트가 /resume으로 지금까지의 진행을 바로 이어받을 수 있습니다. 지식 후보는 직전 체크포인트 뒤에 새로 나온 부분에서만 뽑으므로 같은 후보가 되풀이되지 않습니다. 세션 화면에는 “대화 중 정리 N회”로 보입니다.

서버는 받은 대화에서 아래 왼쪽 열만 남기고 마스킹한 뒤 저장합니다.

서버에 남는 것남지 않는 것
사용자와 에이전트의 발화도구 결과(파일 내용, 명령 출력)
도구 이름과 짧은 인자(명령, 파일 경로, 검색 패턴, 120자까지)시스템 안내문, 하위 에이전트의 대화

Claude Code는 대화록 파일을 그대로 보내므로 도구 결과도 전송은 되지만, 서버가 저장하기 전에 버립니다. 실패한 도구의 오류 출력만 앞 20줄을 남깁니다(마스킹을 거친 뒤). 남긴 대화록은 90일 뒤 지워지며, 그동안은 에이전트가 search_sessions로 본인의 지난 세션을 찾아 읽을 수 있습니다. 보내지 못한 세션은 ~/.conntext/pending/에 남았다가 다음 세션 시작 때 다시 보냅니다.

5.2후보의 갈림길

서버는 저장한 대화에서 두 가지를 뽑습니다. 끝낸 일, 남은 일, 주의점은 진행 상태로 저장해 그 저장소의 이전 상태를 대체합니다. 원인, 결정처럼 남길 만한 문장은 많아야 다섯 개까지 후보로 저장합니다.

후보는 세션 시작 블록에 들어가지 않고, /recall에서 미확인 표시와 함께만 나옵니다. 그다음은 셋 중 하나입니다.

  • 정식 메모가 됨: 웹에서 확인하거나, 에이전트가 답의 근거로 두 번 쓰면 내 메모가 됩니다. 자동으로 올라간 것도 저장 내역에서 되돌릴 수 있습니다.
  • 버림: 웹에서 버리면 더는 나오지 않습니다.
  • 만료: 30일 동안 한 번도 쓰이지 않으면 만료됩니다.

6웹에서 하는 일

터미널에서는 적고 꺼내고, 웹에서는 확인하고 고치고 공유합니다. 왼쪽 레일에서 내 공간과 팀 공간을 바꿀 수 있습니다.

홈
저장소별로 이어서 할 일(진행 상태), 최근 저장 내역과 되돌리기, 확인을 기다리는 후보.
위키
주제 문서. 본문에 근거 메모(m:번호)가 붙고, 대체된 이전 기록도 함께 보입니다. 비슷한 주제는 합칠 수 있습니다.
메모
종류, 출처, 저장소로 걸러 보기. 고치기(새 판으로 대체), 삭제, 후보 확인과 버리기, 팀으로 공유.
에이전트
다음 세션에 들어갈 블록을 저장소별로 미리 보기(4.2), 최근 세션에 실제로 넣은 기록.
세션
수집된 세션과 그 요약, 남은 진행 상태와 후보. 세션 삭제(8.2).
설정
토큰 발급과 회수, 기록 끄기, 내 데이터 내보내기(JSON), 내 데이터 전체 삭제.

7팀 공간

7.1공유는 복사입니다

팀 공간에는 직접 쓰지 않습니다. 내 메모를 검토한 뒤 "팀으로 공유"로 올립니다. 공유는 이동이 아니라 출처가 붙은 복사라서, 원본 m:12는 내 공간에 그대로 남고 팀 공간에 m:37정도현이 생깁니다. 주제 문서 하나를 통째로 올릴 수도 있습니다.

동료의 세션에는 팀 규칙과 팀 지식 색인으로, /recall 결과에는 [팀 지식 · 정도현]처럼 작성자와 함께 들어갑니다. 내가 올린 복사본이 원본과 함께 찾히면 원본만 보여 줍니다.

7.2올리기 전 확인

올리기 전에 미리보기가 나옵니다. 다음은 올라가지 않습니다.

  • 대체됐거나 삭제된 메모
  • 진행 상태
  • 확인하지 않은 후보(먼저 정식 메모로 확인합니다)
  • 이미 이 팀에 올린 메모

접근 제한 문서에서 나온 내용은 한 번 더 확인합니다

제한 문서에서 나온 내용이 든 메모는 팀 전원이 봐도 되는지 확인 표시를 해야 올라갑니다. 세션에서 추출된 뒤 확인한 메모와 마스킹된 메모에는 살펴볼 점이 함께 표시됩니다.

7.3신고

팀 메모는 올린 사람과 팀 관리자만 고치거나 지울 수 있습니다. 동료가 올린 메모가 틀렸다면 웹의 팀 공간에서 무엇이 문제인지 적어 신고합니다. 팀 관리자나 운영자가 확인해 그대로 두거나 지웁니다. 개인 공간의 메모는 운영자도 지울 수 없습니다.

8기록 끄기와 지우기

8.1기록 끄기

끄는 단위에 따라 방법이 다섯 가지입니다.

방법범위효과
<private>…</private>그 구간대화록에서는 장비를 떠나기 전에, 메모에서는 저장 전에 [비공개 처리됨]으로 바뀝니다.
conntext.py pause이 장비세션 기록을 보내지 않습니다. 메모 저장·조회와 세션 시작 맥락은 그대로 됩니다. unpause로 다시 켭니다.
CONNTEXT_OFF=1그 환경 변수가 있는 셸훅이 아무것도 하지 않습니다(맥락도 넣지 않음). 명령어는 저장소 정보 없이 동작해, 새 메모가 전체 범위로 저장됩니다.
.conntext-off그 저장소저장소 최상위에 이 파일을 두면 그 저장소에서 위와 같이 꺼집니다.
웹 설정의 기록 끄기내 계정 전체서버가 받은 세션을 저장하지 않고 버립니다. 모든 장비에 적용됩니다.
터미널
$ python3 ~/.conntext/bin/conntext.py pause이 장비의 세션 기록을 껐습니다. 메모 저장과 조회는 그대로 됩니다.

8.2지우기

  • 메모 하나: /forget이나 웹의 메모 화면에서 지웁니다. 7일 안에는 되돌릴 수 있고, 그 뒤 본문이 실제로 지워집니다.
  • 세션 하나: 웹의 세션 화면에서 지웁니다. 그 세션에서 나온 진행 상태와 확인하지 않은 후보도 함께 지워지고, 확인해서 정식이 된 메모는 남습니다.
  • 내 데이터 전체: 웹의 설정에서 본인 이메일을 입력해 지웁니다. 내 공간의 메모, 주제 문서, 세션, 주입 기록, 알림이 실제로 지워집니다. 팀으로 올린 복사본은 팀의 것이라 남습니다. 지우기 전에 설정에서 JSON으로 내보낼 수 있습니다.

8.3운영자 열람

운영자와 감사자의 화면에는 메모 내용 대신 정책, 비용, 품질 지표, 감사 로그가 나옵니다. 운영자가 내 공간의 메모를 볼 수 있는 경우는 예외 열람 하나뿐이고, 세 가지가 함께 일어납니다.

  1. 운영자가 열람 사유를 10자 이상 적어야 합니다.
  2. 열람 사실과 사유, 건수가 감사 로그에 남습니다.
  3. 나에게 알림이 옵니다: 운영자 ○○○ 님이 내 공간의 메모 N건을 열람했습니다. 사유: …

9문제 해결

훅은 에이전트를 막지 않습니다. 실패하면 조용히 끝내고 ~/.conntext/client.log에 남깁니다. 먼저 이 파일과 status(1.3)를 봅니다.

세션 시작 때 맥락이 들어가지 않습니다

설치 뒤 새로 시작한 세션부터 들어갑니다. CONNTEXT_OFF=1이 설정돼 있거나 저장소에 .conntext-off가 있으면 들어가지 않습니다. 웹의 에이전트 화면에서 그 저장소에 넣을 내용이 있는지 확인합니다.

"토큰이 유효하지 않습니다"

토큰이 회수됐거나 잘못 붙여 넣었습니다. 웹의 설정 > 연결에서 새 토큰을 발급해 setup을 다시 실행합니다.

"Conntext 서버에 연결할 수 없습니다"

서버 주소가 틀렸거나 사내 망에 연결돼 있지 않습니다. ~/.conntext/config.json의 주소를 확인하고, CONNTEXT_URL 환경 변수가 덮어쓰고 있지 않은지 봅니다.

끝낸 세션이 웹에 보이지 않습니다

업로드는 백그라운드에서 하고 실패하면 다음 세션 시작 때 다시 합니다. status에 올리지 못한 세션: N건이 나오면 아직 대기 중입니다. 터미널을 그냥 닫은 세션은 6시간이 지난 뒤 다음 세션 시작 때 올라갑니다. OpenCode는 종료하거나 300초 동안 대화가 없어야 올라갑니다.

분류나 대체가 틀렸습니다

/forget last나 웹의 저장 내역에서 되돌립니다(3.3).

다른 저장소에서 메모가 안 들어갑니다

저장소 범위로 저장된 메모입니다(4.3). 모든 저장소에 적용하려면 --global로 다시 저장합니다.
