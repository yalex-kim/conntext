# 프런트엔드 구현 안내 (구현 담당 에이전트용)

Conntext 웹(소개 페이지, 매뉴얼, 앱)을 만드는 사람이 먼저 읽는 문서다. 방향은 정해져 있고, 여기 적힌 것은 그 방향을 구현할 때 필요한 사실과 기준이다. 적혀 있지 않은 세부는 직접 판단하되, 판단한 것은 보고에 적는다.

## 1. 먼저 읽을 것

1. `PRODUCT.md`: 제품, 사용자, 브랜드 약속.
2. `docs/design/surface-briefs.md`: 표면별 방향 계약. 자기가 맡은 표면의 THESIS, OWN-WORLD, FIRST VIEWPORT를 그대로 구현한다. 더 안전한 해석으로 바꾸지 않는다.
3. `/root/.claude/plugins/cache/impeccable/impeccable/4.8.1/skills/impeccable/reference/craft-floor.md`: UI를 고치기 직전에 읽는다. 품질 하한과 금지 사항이 있다. 맡은 표면의 모드 규칙도 같은 폴더에 있다(`mode-persuade.md`, `mode-read.md`, `mode-operate.md`).
4. 서버 API는 `server/conntext/api.py`가 정본이다. 응답 형태는 실제로 호출해서 확인한다.

## 2. 세계: 케이블 라벨과 프로토콜 규격서

사용자는 연결(Bluetooth, 게이트웨이, OTA)을 다루는 엔지니어다. 이들이 매일 보는 두 가지에서 시각 언어를 가져온다.

- **노란 케이블 라벨**: 케이블에 감아 "이게 어디로 가는 선인지" 적는 표식. Conntext의 메모가 하는 일과 같다. 브랜드의 얼굴이고, conn- 계열(connpass, conntext)을 묶는 장치다.
- **규격서의 그림 문법**: 메시지 시퀀스 차트(참여자 상자, 아래로 내려가는 생명선, 그 사이의 화살표), 프레임 포맷 그림(필드가 칸으로 나뉘고 위에 눈금이 있는 가로 막대), 절 번호.

피할 것 두 가지: 개발자 도구의 기본값(검은 화면 + 네온 강조색)과 메모 앱의 기본값(크림색 종이 + 세리프). 네오브루탈리즘도 아니다. 노랑과 잉크색을 쓰지만 검은 상자, 굳은 오프셋 그림자, 눌린 굵은 글씨는 쓰지 않는다. 선은 가늘고 정확하게.

## 3. 색 (OKLCH, `web/assets/base.css`의 토큰으로)

| 토큰 | 값 | 쓰임 |
|---|---|---|
| `--ink` | `oklch(0.22 0.04 262)` | 본문 글자, 앱 레일 바탕, 선 |
| `--ink-2` | `oklch(0.45 0.035 262)` | 보조 글자 (밝은 바탕에서 4.5:1 이상인지 확인) |
| `--ink-3` | `oklch(0.62 0.03 262)` | 비활성, 눈금 글자 (큰 글자나 장식에만) |
| `--line` | `oklch(0.88 0.012 262)` | 구분선 |
| `--ground` | `oklch(0.975 0.005 250)` | 앱·문서 바탕 (차가운 밝은 회백색. 크림색 금지) |
| `--surface` | `oklch(0.995 0.002 250)` | 패널, 입력 |
| `--marker` | `oklch(0.87 0.17 95)` | 라벨 노랑. 브랜드, 직접 적은 메모, 주 동작 버튼 |
| `--marker-deep` | `oklch(0.78 0.16 88)` | 노랑 위 눌림·테두리 |
| `--team` | `oklch(0.50 0.17 258)` | 팀 지식 |
| `--state` | `oklch(0.60 0.14 158)` | 진행 상태 |
| `--warn` | `oklch(0.72 0.15 62)` | 주의 |
| `--danger` | `oklch(0.55 0.20 27)` | 위험, 삭제 |

노랑 위 글자는 항상 `--ink`다. 노랑 글자를 밝은 바탕에 쓰지 않는다(읽히지 않는다). 색 위의 보조 글자는 회색이 아니라 그 색이나 잉크에서 만든다. 값은 렌더해 보고 대비가 모자라면 조정한다.

## 4. 글꼴 (자체 호스팅, `web/assets/fonts/`)

| 역할 | 글꼴 | 파일 |
|---|---|---|
| 제목(디스플레이) | Paperlogy Bold / ExtraBold | `Paperlogy-Bold.woff2`, `Paperlogy-ExtraBold.woff2` |
| UI와 본문 | SUIT Variable (100–900) | `SUIT-Variable.woff2` |
| 명령어, 메모 id, 저장소 이름, 수치 | D2Coding | `D2Coding-Regular.woff2` |

D2Coding은 코드·데이터·측정값에만 쓴다. "기술적으로 보이려고" 본문이나 제목에 쓰지 않는다. 표의 숫자는 `font-variant-numeric: tabular-nums`. 외부 CDN은 쓰지 않는다(사내 망).

## 5. 등급 라벨 태그: 앱·매뉴얼·소개 페이지가 공유하는 부품

메모 id는 와이어 마커처럼 생긴 작은 태그로 그린다(예: `m:142`, D2Coding). 등급은 색과 **형태** 둘 다로 구분한다. 색만으로 구분하지 않는다.

| 등급 (API의 `tier`) | 한국어 이름 | 형태 |
|---|---|---|
| `mine` | 내 메모 | 노란 채움, 잉크 글자 |
| `team` | 팀 지식 | 파란 채움, 흰 글자, 작성자 이름을 곁에 |
| `candidate` | 세션 자동 추출 · 미확인 | 흰 바탕에 잉크 점선 테두리 |
| `state` | 진행 상태 | 초록 채움 |
| 상태 `superseded` | 대체됨 | 회색, 취소선 |

태그 한쪽 끝은 라벨 테이프를 자른 모양(작은 V자 노치나 사선)으로 만들어 상자와 구분한다. `clip-path`의 꼭짓점은 적게 쓴다.

## 6. 브랜드

- 워드마크: 노란 라벨 안의 `conn` + 라벨 밖의 `text`. 소문자. 모노라인 기하학 글자를 SVG 경로로 직접 그린다(글꼴에 의존하지 않게). connpass도 같은 장치(`conn` 라벨 + `pass`)로 그릴 수 있어야 한다.
- 심볼: 잉크 둥근 사각 위에 오른쪽 끝이 V자 노치로 잘린 노란 라벨 태그, 그 위에 잉크색 `nn`. 워드마크의 `conn` 라벨이 `nn`만 품고 줄어든 모양이다(후보 A로 확정, 2026-11-12). 16px 파비콘은 태그를 칸에 꽉 채우고 `nn`을 굵게 한 별도 판.
- 아이콘은 직접 그린 SVG 한 벌로 통일한다(24 격자, 선 굵기 1.75, 둥근 끝). 유니코드 기호나 이모지로 대신하지 않는다.

## 7. 글쓰기

- 한국어 합쇼체. 결론부터. 과장, 이모지, 느낌표를 쓰지 않는다.
- 제목 위에 작은 라벨(아이브로)을 올리지 않는다. 제목이 혼자 일을 한다.
- 버튼은 하는 일을 말한다("저장", "되돌리기", "팀으로 공유"). 오류는 무엇이 문제이고 어떻게 풀지 말한다.
- 제품이 실제로 하는 것만 쓴다. 고객 수, 성능 수치, 없는 기능을 지어내지 않는다. 화면에 넣는 예시 데이터는 지어내도 되지만 진짜처럼 오해될 자리에는 "예시"라고 밝힌다.
- 용어: 메모, 주제 문서, 진행 상태, 세션 자동 추출 후보(짧게 "후보"), 팀 지식, 주입, 되돌리기, 대체됨, 저장소, 내 공간, 팀 공간.

## 8. 기술 제약

- 빌드 도구 없음. 정적 HTML, CSS, ES modules. 프레임워크·npm 의존성 없음.
- 서버가 `web/`을 그대로 서빙한다. `/` → `web/index.html`, `/manual` → `web/manual.html`, `/app` → `web/app/index.html`, `/assets/...`. 앱 안의 화면 전환은 해시 라우팅(`/app#/wiki/12`)으로 한다.
- 방향 계약(`surface-briefs.md`)의 문구를 HTML 주석, data 속성, 숨은 DOM 등 브라우저로 나가는 어디에도 넣지 않는다.
- 접근성: 의미 있는 마크업, 키보드로 모든 동작 가능, 보이는 포커스 링, `prefers-reduced-motion` 존중.
- 브라우저 기본 표면도 팔레트로 맞춘다: 텍스트 선택 색, 캐럿, 스크롤바, 포커스 링, 밑줄 간격.

## 9. 실행과 확인

- 서버: `http://localhost:7373`에 데모 데이터로 떠 있다. 죽어 있으면 `cd server && nohup python3 -m conntext serve > /tmp/conntext-server.log 2>&1 &`. 서버 코드(`server/`)와 데모 DB를 초기화하는 `seed --reset`은 건드리지 않는다. 다른 사람이 같은 DB로 작업 중이다.
- 데모 로그인(개발용, `POST /api/login {"email": …}` → `{token}`; 이후 `Authorization: Bearer`): `dohyun@conn.example`(개발자, 데이터가 가장 많다), `jimin@conn.example`(팀 관리자), `seoyun@conn.example`(운영자), `eunho@conn.example`(감사자).
- Node 22: `/volume1/dev/.tools/node/bin/node`. Playwright는 `/volume1/dev/vcat/node_modules/playwright`에 있고 크로미움도 설치돼 있다. 스크린샷 스크립트 예시는 `/volume1/dev/.tools/brand/shot.mjs`(이 파일은 고치지 말고, 필요하면 `scripts/` 아래에 자기 것을 만든다. Playwright를 못 찾으면 `NODE_PATH=/volume1/dev/vcat/node_modules`).
- 스크린샷은 `/volume1/dev/conntext/.review/<표면>/` 아래에 둔다. 데스크톱 1440×900과 모바일 390×844, 전체 페이지. 찍기 전에 진입 애니메이션을 끝내거나 꺼서 요소가 빠져 보이지 않게 한다.
- 찍은 파일은 반드시 열어서 본다. 겹침, 잘림, 넘침, 대비, 빈 영역을 확인하고 고친 뒤 한 번 더 찍는다. 두 번이 한도다. 미세 조정마다 찍지 않는다.
- 이 장비의 파일 권한 표시가 `----------`로 보일 수 있다. 정상이다.
