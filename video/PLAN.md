# Conntext 소개 영상 — 장면 계획과 대본 (초안)

> 이 문서는 처음 계획(초안)이다. 확정 대본은 `src/promo/script.ts`, 화풍은 STYLE.md를 본다.

파트 사람들에게 Conntext를 알리는 소개 영상. 만드는 방식은 ConnectivityBook 영상(`bluetoothbook/video`)과 같다.

- Remotion(TypeScript)으로 장면을 만들고, 나레이션은 `script.ts`의 `say` 문장을 타입캐스트(예슬, 감정 `normal` 고정)로 읽는다.
- 화면 자막 `caption`은 같은 문장을 기호·숫자로 적는다. `say`에는 숫자·약어를 소리 나는 대로 적는다.
- 가로 1920×1080, 30fps. 무음판과 나레이션판 두 컴포지션.
- 모든 장면은 제품 화면이나 도식으로 보여 준다. 글자만 있는 슬라이드는 쓰지 않는다.

## 1. 누구에게, 무엇을

- **보는 사람**: Connectivity 파트 개발자. Claude Code나 OpenCode를 이미 쓰고, connpass를 안다.
- **한 가지 메시지**: 적어 둔 맥락이 다음 세션과 다른 에이전트로 이어진다. 같은 설명을 되풀이하지 않아도 된다.
- **보고 나서 할 일**: 웹 설정에서 설치 명령을 복사해 플러그인을 깔고, 첫 `/remember`를 적는다.

## 2. 제목과 훅 후보 (하나를 고른다)

| | 훅(첫 문장) | 제목 |
|---|---|---|
| **A (권장)** | 어제 에이전트한테 설명한 것, 오늘 또 설명하고 있지 않나요? | 어제 한 설명, 오늘 또 하지 마세요 — Conntext |
| B | 스테이징 배포가 무슨 요일이었는지, 에이전트는 모릅니다. 알려 준 적이 있어도요. | 에이전트가 기억하는 팀의 맥락 — Conntext |
| C | 클로드 코드에서 하던 일, 오픈코드에서 이어서 할 수 있나요? | 세션이 바뀌어도 이어지는 일 — Conntext |

A를 권하는 이유: 에이전트를 써 본 사람이면 누구나 겪은 일(매 세션 같은 설명 반복)이고, 뒤의 모든 장면(적기 → 넣기 → 이어받기 → 함께 쓰기)이 이 질문에 대한 답이 된다. B는 한 가지 사례에 묶이고, C는 이어받기 하나만 약속한다.

## 3. 흐름

질문(같은 설명의 반복) → 답의 첫마디(Conntext) → 어떻게(적기 · 넣기 · 절차 · 이어받기) → 믿을 수 있나(신뢰 등급 · 보안) → 함께 쓰기(위키 · 팀) → 정리와 시작.

## 4. 장면표

길이는 타입캐스트 실측 속도(공백·문장부호 빼고 초당 약 6.5자)에 앞뒤 여백 0.9초를 더한 어림이다. 예시 데이터는 데모 계정(정도현, 저장소 `ble-gateway`)의 메모를 쓴다.

### S1 `hook` — 같은 설명의 반복 (약 13초)

**화면**: 3D 책상 앞의 개발자(캡슐 몸, 공 머리)와 모니터 두 대. 왼쪽 모니터에는 '어제 세션', 오른쪽에는 '오늘 세션'이라고 적혀 있다. 왼쪽에서 개발자가 말풍선으로 설명한 세 가지(`make test-hw-sim으로 돌려 줘`, `broker 먼저 재시작`, `스테이징 배포는 목요일`)가 오른쪽에서 똑같이 다시 나온다. 오른쪽 에이전트는 `pytest`를 직접 불러 빨간 실패가 뜬다. 카메라가 오른쪽 모니터로 천천히 다가간다.

| say | caption |
|---|---|
| 어제 에이전트한테 설명한 것, 오늘 또 설명하고 있지 않나요? | 어제 에이전트한테 설명한 것, 오늘 또 설명하고 있지 않나요? |
| 테스트는 어떤 명령으로 돌리는지, 게이트웨이는 무엇부터 재시작하는지. | 테스트는 어떤 명령으로 돌리는지, 게이트웨이는 무엇부터 재시작하는지. |
| 세션이 바뀌면, 에이전트는 처음부터 다시 시작합니다. | 세션이 바뀌면 에이전트는 처음부터 다시 시작합니다. |

### S2 `brand` — Conntext (약 6초)

**화면**: 랜딩 페이지 인트로를 그대로 쓴다. `conntext` 글자의 `nn`이 노란 라벨 태그 아이콘으로 바뀌고, 아이콘이 잠깐 커졌다가 왼쪽 위로 붙는다. 아래에 한 줄 소개가 나온다.

| say | caption |
|---|---|
| 콘텍스트는, 적어 둔 맥락을 다음 세션과 다른 에이전트로 이어 주는 서비스입니다. | Conntext — 적어 둔 맥락이 다음 세션과 다른 에이전트로 이어집니다 |

### S3 `remember` — 적기 (약 14초)

**화면**: 터미널(Claude Code)에 `/conntext:remember 스테이징 배포는 목요일 오전만 가능하도록 변경됨. 화요일은 QA 회귀 테스트와 겹친다`를 친다. 결과 줄이 찍힌다: `저장됨 m:12 → [스테이징 배포] · 지식 · 범위: 저장소 ble-gateway` / `이전 메모 1건 대체: "스테이징 배포는 화요일 오전만 가능"`. 이어서 도식: 메모 카드가 네 칸 서랍(지시·선호 / 지식 / 절차 / 진행 상태) 가운데 '지식'으로 들어가고, 같은 칸의 화요일 카드는 회색 '대체됨'으로 접혀 이력에 남는다.

| say | caption |
|---|---|
| 기억해 둘 것은 리멤버 명령으로, 평소 말투 그대로 적습니다. | 기억해 둘 것은 /remember로, 평소 말투 그대로 적습니다. |
| 콘텍스트가 지시인지, 지식인지, 절차인지 나누고, 이미 있는 메모와 견줍니다. | Conntext가 지시·지식·절차를 나누고, 이미 있는 메모와 견줍니다. |
| 배포 요일이 바뀌었다면, 옛 메모는 이력으로 남고 새 메모가 적용됩니다. | 배포 요일이 바뀌면 옛 메모는 이력으로 남고 새 메모가 적용됩니다. |

### S4 `inject` — 다음 세션이 알고 시작 (약 16초)

**화면**: 새 세션을 연다. 웹 '에이전트' 화면의 프레임 그림(가로 막대 = 토큰 예산, 칸 = 지시·선호 / 팀 규칙 / 진행 상태 / 절차 색인 / 지식 색인)이 왼쪽부터 채워진다. 칸이 채워질 때 그 칸의 실제 줄 하나씩이 위로 떠오른다(`ble-gateway에서는 테스트를 반드시 make test-hw-sim으로…`, `게이트웨이 재시작할 때 → 게이트웨이 재시작 순서 [t:3]`, `스테이징 배포`). 끝에 오른쪽 터미널에서 에이전트가 `make test-hw-sim`을 바로 부른다.

| say | caption |
|---|---|
| 다음 세션을 열면, 콘텍스트가 맥락을 먼저 넣어 둡니다. | 다음 세션을 열면 Conntext가 맥락을 먼저 넣어 둡니다. |
| 늘 지킬 지시와 선호, 지난번 진행 상태, 그리고 절차와 지식의 목록입니다. | 늘 지킬 지시·선호, 지난번 진행 상태, 절차와 지식의 목록 |
| 본문은 필요할 때만 꺼내서, 정해진 예산을 넘지 않습니다. | 본문은 필요할 때만 꺼내, 정해진 예산(1,500토큰)을 넘지 않습니다. |
| 질문과 관련이 깊은 메모가 있으면, 그 자리에서 함께 건넵니다. | 질문과 관련이 깊은 메모가 있으면 그 자리에서 함께 건넵니다. |

### S5 `procedure` — 절차는 따로 (약 9초)

**화면**: 사용자가 `게이트웨이 재시작해 줘`를 보낸다. 절차 색인 줄 `게이트웨이 재시작할 때 → 게이트웨이 재시작 순서`가 빛나고, 에이전트가 절차 문서를 펼친다. 번호 단계 1 `mqtt-broker` → 2 `ble-bridge`가 차례로 체크되고, `## 주의: 반대로 하면 재연결 폭주`가 옆에 붙는다.

| say | caption |
|---|---|
| 작업하는 방법은 절차로 따로 모읍니다. | 작업하는 방법은 절차로 따로 모읍니다. |
| 에이전트는 게이트웨이를 재시작하기 전에 그 절차를 꺼내, 적힌 순서대로 따릅니다. | 게이트웨이를 재시작하기 전에 그 절차를 꺼내, 적힌 순서대로 따릅니다. |

### S6 `handoff` — 다른 에이전트로 이어받기 (약 12초)

**화면**: 왼쪽 Claude Code, 오른쪽 OpenCode 창. 왼쪽 대화가 길어지는 동안 위쪽 눈금이 열 턴마다 한 번씩 찍히며 진행 상태 카드(완료 / 남은 일)가 갱신된다. 오른쪽에서 `/resume`을 치면 카드가 오른쪽으로 건너가 펼쳐진다: `남은 일: broker/acl_cache.py의 TTL 확인`.

| say | caption |
|---|---|
| 하던 일은 진행 상태로 정리됩니다. | 하던 일은 진행 상태로 정리됩니다. |
| 세션이 끝날 때, 그리고 긴 세션은 열 턴마다 한 번씩입니다. | 세션이 끝날 때, 긴 세션은 10턴마다 |
| 그래서 클로드 코드에서 하던 일을, 오픈코드에서 리줌 한 번으로 이어받습니다. | Claude Code에서 하던 일을 OpenCode에서 /resume 한 번으로 이어받습니다. |

### S7 `trust` — 무엇을 믿을 수 있나 (약 11초)

**화면**: 메모 태그 네 가지를 색과 모양으로 나란히: 내 메모(노란 실선), 팀 지식(파란 실선 + 작성자), 세션 자동 추출·미확인(점선), 진행 상태(초록). 세션에서 뽑힌 점선 후보 하나를 사람이 '확인'하면 실선으로 바뀌어 세션 시작 목록에 들어간다.

| say | caption |
|---|---|
| 세션 대화에서 저절로 뽑힌 내용은, 미확인 후보로 따로 표시됩니다. | 세션에서 저절로 뽑힌 내용은 '미확인' 후보로 표시됩니다. |
| 내가 확인하기 전에는 세션 시작 때 넣지 않으니, 잘못 뽑힌 내용이 에이전트를 끌고 가지 않습니다. | 확인 전에는 세션 시작 때 넣지 않습니다. |

### S8 `team` — 위키와 팀 공간 (약 12초)

**화면**: 웹 위키의 '스테이징 배포' 문서. 문장 끝의 근거 번호를 누르면 원문 메모가 옆에 열린다. 이어서 메모의 '팀으로 공유' → 팀 공간(Connectivity 팀). 동료(오지민)의 세션 시작 블록에 `팀 지식 색인`이 생기고, recall 결과에 `[팀 지식 · 정도현]`이 붙는다.

| say | caption |
|---|---|
| 쌓인 메모는 주제별 위키 문서가 되고, 문장마다 근거 메모가 달립니다. | 쌓인 메모는 주제별 위키 문서가 되고, 문장마다 근거 메모가 달립니다. |
| 쓸 만한 지식은 팀 공간으로 공유합니다. | 쓸 만한 지식은 팀 공간으로 공유합니다. |
| 그러면 동료의 에이전트도, 누가 적었는지와 함께 그 지식을 씁니다. | 동료의 에이전트도 작성자와 함께 그 지식을 씁니다. |

### S9 `safe` — 민감 정보와 운영 (약 11초)

**화면**: 메모에 섞인 `api_key = sk-live-…`와 휴대전화 번호가 저장 직전에 `[마스킹]`으로 바뀐다. `<private>…</private>` 구간은 장비를 떠나기 전에 지워진다. 운영자 화면은 메모 내용 대신 지표와 정책만 보이고, 예외 열람에는 사유 입력과 본인 알림이 따라붙는다.

| say | caption |
|---|---|
| 토큰이나 비밀번호, 전화번호는 저장하기 전에 가립니다. | 토큰·비밀번호·전화번호는 저장하기 전에 가립니다. |
| 운영자 화면에는 메모 내용 대신 지표와 정책만 보이고, 예외로 열어 보면 사유가 남고 본인에게 알림이 갑니다. | 운영자는 내용 대신 지표·정책만 봅니다. 예외 열람은 사유가 남고 본인에게 알립니다. |

### S10 `outro` — 정리와 시작 (약 10초)

**화면**: S1의 3D 책상으로 돌아온다. 이번에는 오른쪽 '오늘 세션'에서 말풍선 없이 에이전트가 `make test-hw-sim`을 바로 부르고 초록 통과가 뜬다. 그 위에 네 단계 흐름 그림(적기 → 넣기 → 이어받기 → 함께 쓰기)이 얹히고, 끝에 Conntext 로고와 '설정 → 연결에서 설치 명령 복사'가 나온다.

| say | caption |
|---|---|
| 한 번 적어 두면, 다음 세션은 알고 시작합니다. | 한 번 적어 두면, 다음 세션은 알고 시작합니다. |
| 다른 에이전트도, 동료의 에이전트도요. | 다른 에이전트도, 동료의 에이전트도. |
| 웹 설정에서 설치 명령을 복사해, 오늘 세션부터 써 보세요. | 웹 설정 → 연결에서 설치 명령을 복사해 오늘부터 써 보세요. |

## 5. 사실 확인 (대본의 문장마다 근거)

| 문장 | 근거 |
|---|---|
| 종류를 나누고 이미 있는 메모와 견준다 | `pipeline.analyze`: 종류(지시·선호/지식/절차/진행 상태), 관계(중복·갱신·보충·관련) 판정 |
| 옛 메모는 이력으로 남는다 | 갱신이면 이전 메모가 `superseded`, 원문은 바꾸지 않음 |
| 세션 시작 때 지시·진행 상태·절차·지식 목록, 예산 안 | `retrieval.build_context`, 정책 `injection.token_budget` 1500 |
| 질문과 관련 깊은 메모를 함께 건넨다 | #12, 정책 `prompt_recall`(기본 켬, 최대 3개, 내용어 둘 이상 일치) |

| 미확인 후보는 확인 전 세션 시작 때 넣지 않는다 | 주제 색인은 `trust!='low'` 메모만, 지시는 `trust='high'`만 |
| 근거 메모가 달린 위키 | 주제 문서 `[m:ID]` 인용, 웹의 근거 번호 |
| 작성자와 함께 팀 지식을 쓴다 | recall `[팀 지식 · 작성자]`, 팀 지식 색인 |
| 저장 전에 가린다 / private 구간 | `masking` 기본 규칙(토큰·비밀번호 대입, 휴대전화 번호 등), 클라이언트의 `<private>` 처리 |
| 운영자는 지표·정책만, 예외 열람은 사유·알림 | 운영 모듈 설계(예외 열람 = 사유 + 감사 로그 + 본인 알림) |

S7에서 빼 둔 사실: 미확인 후보는 답에 두 번 쓰이면 확인 없이 정식 메모가 된다(`candidate_promote_uses`). 영상에서는 단순하게 "확인하기 전에는 넣지 않는다"까지만 말한다. 이 말 자체는 맞다(승격 전까지는 넣지 않음).
